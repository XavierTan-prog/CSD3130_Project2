## Build (Windows, Visual Studio 2022 + vcpkg)

One-time vcpkg setup:

```powershell
git clone https://github.com/microsoft/vcpkg C:\dev\vcpkg
C:\dev\vcpkg\bootstrap-vcpkg.bat
```

Then double-click `run.bat`. It takes no arguments: it generates the Visual
Studio solution in `build\` (finding Visual Studio's CMake by itself) and
opens it. If vcpkg is not at `C:\dev\vcpkg`, set `VCPKG_ROOT` first.

Two more scripts, also argument-free:

| Script | What it does |
| --- | --- |
| `clean.bat` | Deletes `build\` and the `bench_*.png` outputs. Close Visual Studio first. |
| `rebuild.bat` | Runs `clean.bat` then `run.bat`: regenerates the solution from scratch and opens it. |

Everything else is launched from Visual Studio. Right-click a project >
**Set as Startup Project**, then press **Ctrl+F5** (run) or **F5** (debug):

| Project | What it does | Default arguments |
| --- | --- | --- |
| `seam_carve` (default) | Asks which image, target size and method to use, resizes, shows original and result side by side, then offers to run again | none (interactive) |
| `benchmark` | Times the three methods | `images/input/sample.png 10` |
| `tests` | Runs the unit tests | none |

`seam_carve` lists the images in `images\input\`; pick one by number or type
(or drag in) any file path. Pressing Enter accepts the default shown in
brackets. The result is saved to `images\output\<name>_<method>.png`.

After each result (once you close the image window) it asks what to do
next: `1` resizes the same image again (try another size or method), `2`
picks another image, `3` quits. Running the same image with the same method
again overwrites its previous output file.

Answer `y` to "Show each seam as it is removed?" for the step-by-step view:
each seam is drawn in red on the current image before it is removed. In
that window, Space pauses or resumes, N shows the next seam while paused,
and Esc skips to the result (carving still finishes).

The solution is generated by CMake: to add or remove source files, edit
`CMakeLists.txt` rather than the solution, then build again.

The same steps by hand (the first configure builds OpenCV and is slow):

```powershell
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=C:/dev/vcpkg/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

## Run from a terminal (optional)

```powershell
# seam_carve <input> <output> <width> <height> [dp|greedy|graphcut] [--no-show] [--steps[=MS]]
# (--no-show skips the preview window; --steps shows every seam, MS milliseconds each, default 30)
build\Release\seam_carve.exe images\input\Broadway_tower_edit.jpg images\output\Broadway_tower_edit_dp.png 1071 726 dp
build\Release\seam_carve.exe images\input\sample.png images\output\sample_graphcut_190x145.png 190 145 graphcut --no-show
build\Release\seam_carve.exe images\input\sample.png images\output\sample_dp.png 150 120 dp --steps=100

# benchmark <input> <seams-to-remove>
build\Release\benchmark.exe images\input\sample.png 10
```

## Reproducing the results (report figures and timings)

The figures and timings in the report and slides come from four small
programs in `bench/results/`, built with the rest of the solution. They call
the same library functions as `seam_carve` and do not change it.

Double-click `bench\results\run_results.bat` (after `run.bat` has been run
once). It builds the Release configuration, runs the unit tests and the four
programs, and takes about 2 minutes. Everything it prints is saved to
`images\output\results\windows_output.txt`, and the figures go to
`images\output\results\` (ignored by Git).

| Program | What it checks or measures |
| --- | --- |
| `results_grid` | The 5 x 5 worked example: DP and graph cut give cost 8, greedy 23 |
| `results_eval` | Seam overlays and outputs for DP, greedy and graph cut; time per seam at five image sizes; seam energy of each method; DP memory and multithreading experiments |
| `results_omp` | Serial DP against OpenMP DP |
| `results_gcbig` | One graph-cut seam on the two largest image sizes (about 35 s) |

What to look for: the tests pass, graph cut's seam energy always equals DP's,
greedy's is higher, and graph cut is far slower than DP. Times depend on the
machine; the rankings should not.
